# 風險管理

> **第一守則：活下來。**
>
> 量化策略失敗的首要原因不是「策略不好」，而是**部位過大、破產前無法等到策略生效**。風控的目的不是放大報酬，而是保證系統在最壞情境下仍能存活。

## 資金分層

```
總資產
 ├── 生活 + 緊急預備金（6 個月）     ← 永不動用
 ├── 長期投資（ETF、定存等）         ← 獨立管理
 └── 量化交易專戶                    ← 本系統使用
      ├── 保證金預留（活錢）
      └── 緩衝資金（避免追繳）
```

**量化專戶金額**應為「即使歸零也不會影響生活」的規模。建議從總資產 5% 起步。

## 部位大小（Position Sizing）

### 初期（Phase 3 小額實盤）
- **固定 1 口小台（MXF）**
- 目的：驗證系統運行，不是賺錢

### 成熟期（Phase 4+）
採「**固定百分比風險**」（Fixed Fractional Risk）：

```
每筆最大風險金額 = 專戶權益 × r            # r 建議 0.5% – 1%
每筆最大風險點數 = 進場價 × stop_loss_pct  # 或 ATR(14) × k
下單口數        = floor(每筆最大風險金額 / (風險點數 × 200))
```

範例：
- 專戶 NT$1,000,000，r = 1% → 單筆風險上限 NT$10,000
- 進場 17,000，ATR 150 點 × 2 = 300 點風險
- 口數 = 10,000 / (300 × 200) = 0.17 口 → 僅可交易 MXF（50 元/點）
  - 10,000 / (300 × 50) = 0.67 → 仍不足 1 口
  - 表示專戶太小，需放大至 NT$1,500,000 以上才安全

## 停損（Stop Loss）

### Phase 1（策略原生）
EMA 死亡交叉即為出場 → **隱含停損**

### Phase 2+（加上硬停損）
防止極端行情下 EMA 反應不及：
- **硬停損**：進場價 − ATR(14) × 2
- **緊急停損**：進場價 − 3% （絕對下限）

兩者取較近者。觸價立即平倉，**不等 K 棒收盤確認**。

## 組合層級風控

| 規則 | 觸發條件 | 動作 |
| --- | --- | --- |
| **單日虧損上限** | 單日權益跌幅 > 3% | 當日不再進場 |
| **單週虧損上限** | 單週權益跌幅 > 6% | 該週剩餘時間不再進場 |
| **單月虧損上限** | 單月權益跌幅 > 10% | 進入 Kill Switch |
| **最大回撤** | 權益回撤 > 20% | 進入 Kill Switch |

### Kill Switch
觸發後：
1. 立即平倉所有部位
2. 停止所有新進場訊號
3. 發送告警（Telegram）
4. **手動**分析原因、人工解除後才恢復
5. 每次觸發產生 post-mortem 文件

## 保證金管理

- **保證金使用率上限：50%**（即帳戶資金 / 所需保證金 ≥ 2 倍）
- 避免小幅逆勢就被追繳、強平
- 大台原始保證金約 NT$184,000／口（隨市況調整）
- 小台原始保證金約 NT$46,000／口

## 特殊情境

| 情境 | 處理 |
| --- | --- |
| **結算日** | 最後交易日 13:30 前強制平倉；當週禁止新進場 |
| **節假日前** | 長假前最後一個交易日收盤前平倉（避免跳空風險） |
| **重大事件日** | 央行理監事會、FOMC、選舉等：日曆中標記，當日暫停交易 |
| **系統斷線 > 5 分鐘** | 自動進入保守模式（可平倉、不開新倉） |
| **券商 API 異常** | 切換備用通道或手動介入；送告警 |
| **漲跌停鎖死** | 部位無法平倉：記錄、持續嘗試、盤後人工確認 |
| **行情異常跳動** | 單根 K 棒 > 5% 跳空：暫停該訊號、人工確認 |

## 手動覆寫（Manual Override）

系統設計允許手動：
- **全部平倉**（`python -m twquant.admin flatten_all`）
- **暫停交易**（`python -m twquant.admin pause`）
- **調整部位大小**（config 熱更新）

但禁止：
- 手動修改已發生的交易紀錄
- 繞過 Kill Switch 強制進場

## 檢查清單（每日盤後自動執行）

- [ ] 今日實際損益 = 權益變化
- [ ] 持倉口數 = 系統狀態紀錄
- [ ] 保證金使用率在上限內
- [ ] 所有訊號都有對應訂單（或被風控攔截的紀錄）
- [ ] 無「殭屍部位」（系統不知但券商有）

任何不一致 → 告警 + 停止新進場。

## 心理因素（雖然是系統交易，但你還是人）

- **不看盤**：盤中不要一直看權益曲線
- **不即興修改參數**：策略修改必須有書面理由並重新回測
- **虧損期要忍住**：趨勢策略本就有長時間震盪期；統計上 40% 時間在回撤
- **不用槓桿擴張**：賺錢時不加倉至超過風控允許範圍
